# Алмазная змейка: мир и нагрузка

Параметры находятся в `assets/snake-config.js`: мир 6000×6000, 60 участников,
20 серверных шагов/с, 90 секунд игры, 1500 обычных и 100 редких кристаллов.
Начальный обратный отсчёт — дополнительные 5 секунд. Возрождение занимает
2 секунды, после появления действует защита 3 секунды.

## Передача данных

- Сервер рассчитывает движение и столкновения через пространственную сетку.
  Шаги назначаются по монотонным срокам с компенсацией задержек таймера Windows,
  чтобы погрешность `setInterval` не уменьшала фактический TPS.
- Индивидуальное состояние окрестности головы передаётся до 10 раз/с.
  Размер области соответствует максимальному размеру клиентского вида с запасом.
- Тела передаются прореженными точками с целочисленными смещениями.
- Видимые кристаллы, ТОП-10, место игрока и точки мини-карты обновляются раз/с.
  Собранные кристаллы удаляются промежуточными сообщениями. Полный список
  окрестности периодически восстанавливает состояние после пропуска пакетов.
- Если сокет ещё передаёт прошлый пакет, новое промежуточное состояние пропускается.
  Управляющие сообщения тоже не накапливаются. Клиент отправляет направление
  не чаще 10 раз/с; сервер дополнительно ограничивает частоту принятия направления.
- Во время мини-игры участнику не пересылается скрытая карта завода и её отрисовка
  приостанавливается. Правила основной игры не изменены.
- Камера следует за головой и отдаляется при росте. Рисуются только видимые объекты;
  DPR ограничен 1,5, размытие свечения на игровом поле отключено.

## Воспроизводимый нагрузочный тест

```powershell
npm.cmd test
node scripts/snake-load.cjs 60
# Дополнительный запуск:
node scripts/snake-load.cjs 50
```

Тест запускает отдельный серверный процесс, подключает настоящие WebSocket-клиенты
к одной комнате и отправляет направления в течение полного раунда. Он проверяет
сумму очков по удалённым кристаллам, единственность результатов и наград,
отсутствие ошибок протокола и очистку раунда.

В JSON-отчёте: CPU сервера в процентах одного ядра, пиковый RSS процесса,
время серверного шага, задержка event loop, фактическая частота шагов,
возраст сообщений при получении, объём JSON-трафика и среднее число подробно
переданных змеек. CPU и RSS не включают процесс виртуальных клиентов.
Задержка измеряется на одном компьютере; это не RTT сети Wi-Fi или Cloudflare.

## Результат проверки 60 участников

Полный запуск: 95,76 с с обратным отсчётом и проверкой повторных наград.
60 результатов, ошибок начисления очков — 0.

| Показатель | Результат |
|---|---:|
| CPU сервера, доля одного ядра | 22,1% |
| Пиковый RSS сервера | 186,9 МиБ |
| Возраст сообщения, p95 / p99 | 25 / 40 мс |
| Серверный шаг, p99 / максимум | 38,6 / 106,4 мс |
| Event loop, p99 | 45,7 мс |
| Средний трафик на участника | 174 кбит/с |
| Среднее число подробных змеек в пакете | 6,15 из 60 |

Трафик полного раунда уменьшен с 286,4 до 119,3 МиБ после дополнительной
оптимизации тел и кристаллов. Это измерения локальной среды, а не гарантия
производительности любого ноутбука и школьной сети.

Три браузерные страницы проверены с размерами 1440×900, 390×844 и 768×1024:
общий мир, раздельные области видимости, управление, мини-карта, сворачивание
рейтинга, переподключение и возврат с однократной наградой. Мобильная эмуляция
показала около 60 RAF-кадров/с. Физические телефоны и реальный канал Cloudflare
в этот нагрузочный прогон не входили; перед мероприятием нужна проверка на
целевом ноутбуке и школьном Wi-Fi.
