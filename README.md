# Шахта Знаний · СОТА

Игра для выездных мероприятий. На ноутбуке организатора работает Node.js-сервер, школьники открывают игру в браузере через Cloudflare Tunnel. Устанавливать приложения на телефоны не требуется. Все комнаты, игроки и результаты находятся только в RAM. После остановки сервера они удаляются.

Организатор работает в обычной папке проекта и запускает **`start.bat`**. Отдельная папка `portable` ему не нужна. Node.js, cloudflared и зависимости подготавливаются на ноутбуке один раз заранее.

## Первоначальная подготовка

### Подготовка ноутбука один раз

1. На ноутбуке организатора установите Node.js 22 или новее и скачайте этот репозиторий.
2. Запустите `prepare.bat`: он устанавливает зависимости по `package-lock.json` и собирает TypeScript. Для этого нужен интернет. Альтернатива: `npm ci`, затем `npm run build`.
3. Установите `cloudflared` из [официального источника](https://developers.cloudflare.com/tunnel/downloads/) и добавьте его в PATH либо положите `cloudflared.exe` в папку `runtime`. Также поддерживается переменная `CLOUDFLARED_PATH` с полным путём к файлу.
4. Закройте старый сервер игры, если он занимает порт 8787. Запустите `start.bat`.

### Необязательная переносимая сборка для разработчика

На компьютере подготовки с Node.js, npm, PowerShell и интернетом выполните:

Этот раздел не нужен организаторам с уже подготовленными ноутбуками.

```powershell
npm run portable
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd run portable`.

Сценарий `scripts/build-portable.ps1` создаёт папку `portable` с собранным сервером, рабочими зависимостями, Node.js и `cloudflared.exe`. Node.js скачивается с nodejs.org и проверяется по SHA-256; cloudflared — из официального GitHub-репозитория, с проверкой digest при наличии. Версии записываются в `portable/runtime/versions.json`.

Скопируйте **папку целиком** на ноутбук организатора. Устанавливать Node.js и npm на каждом выезде не требуется. Запускайте `portable/start.bat`. Переносимая сборка рассчитана на Windows x64. Для другой архитектуры подготовьте соответствующие исполняемые файлы. Для повторной сборки сначала переименуйте предыдущую папку `portable` — сценарий не удаляет её автоматически.

## Запуск на мероприятии

1. Подключите ноутбук к интернету, например к мобильной точке доступа. Подключите питание и отключите переход в сон на время игры.
2. Запустите `start.bat` в обычной папке проекта. Он проверит установленный Node.js и зависимости, запустит сервер и туннель, затем откроет панель организатора.
3. Автоматически откроется локальная панель организатора. Дождитесь сообщения «Игра доступна по публичной ссылке. HTTPS-проверка прошла». Само подключение cloudflared ещё не подтверждает, что публичный адрес работает.
4. Школьники сканируют QR или открывают публичную HTTPS-ссылку. Их телефоны могут находиться в других сетях и использовать собственный мобильный интернет.
5. В панели организатора выберите город и нажмите **«Создать комнату»**. Сообщите группе пятизначный код. Ученики открывают сайт, выбирают скин, вводят этот код и нажимают **«Войти в комнату»**.
6. Ученики появляются в комнате ожидания: видят код и список участников. В панели организатора отображаются подключённые игроки и выбранные скины. До старта свет не расходуется, двигаться и отвечать на вопросы нельзя.
7. Когда группа собралась, нажмите **«Начать игру»** в строке нужной комнаты. Все подключённые ученики одновременно появляются в общей шахте. Запуск доступен только организатору; пустую комнату запустить нельзя.
8. Для приглашения сразу в нужную комнату можно отправить ссылку вида `https://текущий-адрес/?room=ABCDE`. Поле кода заполнится автоматически; участник выберет скин и подтвердит вход. Если игра уже началась, поздний участник присоединяется к текущей шахте.

Окно запуска и ноутбук должны оставаться включёнными. Для корректной остановки нажмите **Ctrl+C** в окне запуска: остановятся сервер и принадлежащий ему процесс cloudflared. Кнопки в панели завершают игровые комнаты, оставляя сервер готовым к следующей группе.

Стандартный порт — 8787, слушает только `127.0.0.1`; открывать входящий порт роутера не требуется. Для другого порта задайте переменную `PORT` до запуска.

## Cloudflare: временная ссылка и постоянный домен

По умолчанию используется **Quick Tunnel**. Аккаунт и предварительная настройка Cloudflare не требуются, но cloudflared должен быть подготовлен, а сеть должна разрешать исходящее подключение к Cloudflare. При каждом новом туннеле ссылка `trycloudflare.com` меняется. QR-код строится локально по актуальному адресу, без внешних сервисов генерации QR.

Quick Tunnel предназначен для тестирования, не имеет гарантии доступности и ограничен Cloudflare числом одновременных запросов. Перед выездом обязательно проверьте реальную работу через мобильные сети. Для регулярных мероприятий предпочтителен постоянный именованный туннель: [документация Cloudflare](https://developers.cloudflare.com/tunnel/get-started/).

Для постоянного домена:

1. В аккаунте Cloudflare создайте именованный Tunnel и публичный hostname, направленный на `http://127.0.0.1:8787`.
2. Скопируйте `event-config.example.json` в `event-config.local.json`, задайте `mode: "named"` и `publicUrl: "https://ваш-домен"`.
3. Для удалённо управляемого туннеля передайте **серверную переменную `TUNNEL_TOKEN`** в окружение запуска. Не записывайте токен в Git и не передавайте его игрокам. Для локально настроенного туннеля вместо токена можно указать `tunnelName`; credentials и config cloudflared должны быть заранее подготовлены под Windows-пользователем организатора.
4. Проверьте запуск заранее. Если в `%USERPROFILE%\.cloudflared` уже есть `config.yml`, Quick Tunnel может не запускаться: используйте именованный туннель или уберите конфликтующую конфигурацию из этого профиля.

HTTPS и WSS завершаются на Cloudflare; локальное соединение с сервером идёт по loopback. Эта архитектура не использует Vercel, Redis или другие базы данных.

## Игровые правила и восстановление

Сохранены шахта 23×15 клеток, генерация пещер, города, скины, тап-маршрут, клавиши, кристаллы, сложные алмазы, вопросы с вариантами/«верно или нет»/ползунком, подсказка за свет, штраф за выход из вопроса, аптечки, масло, фонарь, силы, серия, лестница и финал с фотографией СОТЫ. Вопросы редактируются в `questions.json` до запуска сервера; неверная структура останавливает запуск с ошибкой.

Внутри комнаты карта, кристаллы, бонусы на карте и переход в следующую шахту общие. Очки, фонарь, силы и серия — у каждого игрока свои. Вопрос решает тот, кто подошёл к кристаллу первым; другие могут исследовать шахту. Сервер проверяет направление шага, стены, частоту движения, номер уровня, позицию для вопроса, владение кристаллом, допустимость ответа, повторное начисление очков и условия открытия лестницы. Одноразовые бонусы нельзя собрать дважды. Уход одного игрока к открытой лестнице переводит живых участников комнаты в следующую шахту.

При обрыве связи клиент автоматически повторяет подключение с увеличением задержки до 5 секунд. На время обрыва ввод блокируется. Временный ключ в `sessionStorage` восстанавливает того же игрока, его позицию и очки в течение **60 секунд**, в том числе в комнате ожидания. Отключённый игрок не расходует свет. Незавершённый вопрос освобождает кристалл без штрафа; подтверждённый ответ сохраняется. После перезапуска сервера или истечения времени восстановления нужно войти в комнату снова. Пустая начатая комната очищается через минуту, пустая комната ожидания — через 30 минут; неактивные отключённые игроки удаляются через минуту.

## Панель и защита

Панель показывает состояние сервера/туннеля, текущую ссылку, QR, число подключений и комнаты со списками участников; позволяет создавать комнаты, запускать группу и завершать одну или все сессии. Создание и запуск удалены из ученического WebSocket-протокола. Панель доступна только с loopback-адреса и локального Host ноутбука. Административный API дополнительно требует случайный ключ, который запуск передаёт в локальную ссылку. Проксированные запросы к административным функциям отклоняются. Ключ не публикуется в QR или игровых снимках состояния.

Ограничения приложения: до **20 комнат**, **16 игроков в комнате**, **120 зарезервированных игроков**, **160 открытых WebSocket-соединений**. Пределы — защитные ограничения, а не обещание производительности: реальную нагрузку надо проверить на ноутбуке и сети мероприятия. Входящие сообщения проверяются Zod, размер пакета ограничен 4 КиБ, есть лимит частоты и heartbeat. Медленные соединения с растущей очередью закрываются. Технические сообщения выводятся в консоль без имён, IP и содержимого ответов школьников.

## Проверки

```powershell
npm.cmd test
```

Команда собирает TypeScript и выполняет тесты генерации/достижимости, валидации, стен и движения, изоляции комнат, владения кристаллом, подсказки, правильного/неверного ответа, ползунка, штрафа, смерти, общих переходов и победы, восстановления и очистки RAM; HTTP/WebSocket-тесты проверяют два клиента, токен восстановления, закрытие сессии, QR, защиту панели, лимиты размера и частоты.

Дополнительно доступен `node scripts/check-browser.cjs` при установленном Playwright и Chromium. Он проверяет два мобильных браузера (360 и 390 пикселей), вход, карту, движение, ответ, общий кристалл, восстановление и панель с QR. Тестовые наблюдения внедряются только в перехваченный HTML; в рабочую страницу не добавлены.

При наличии собранной папки `portable` команда `node scripts/check-tunnel.cjs` запускает её без открытия браузера, проверяет публичные HTTPS/WSS и останавливает свои процессы. Это реальная временная публикация через Quick Tunnel, для неё нужен интернет.

Проверено при реализации: сборка TypeScript, 12 автоматических тестов, два мобильных браузера, восстановление соединения, создание комнаты в панели, ожидание без расхода света, одновременный старт группы, панель и QR. Дополнительные тесты проверяют публичный health-check, совпадение экземпляра игры и распознавание Cloudflare 1033. Ранее также проверены сборка Windows x64, запуск переносимого Node.js и корректная остановка. Полный внешний маршрут и настоящие Android/iPhone требуют ручной проверки по инструкции ниже.

### Если публичная ссылка не открывается

- Локальная игра `http://127.0.0.1:8787/` и публичная ссылка — разные проверки. Если локальная страница работает, а Cloudflare возвращает HTTP 530 / Error 1033, по этому адресу Cloudflare не находит активный туннель. Один запущенный процесс cloudflared ещё не подтверждает доступность ссылки.
- Остановите запуск через Ctrl+C и снова запустите `start.bat`. Используйте только текущую ссылку из панели. При ошибке внешний health-check повторяется автоматически; панель показывает результат вместо преждевременного сообщения о готовности.
- Если 1033 сохраняется, проверьте другую сеть или мобильную точку доступа и сообщение состояния туннеля. Это диагностика сетевого подключения, а не способ снять предупреждение браузера.
- Красное предупреждение Яндекс Браузера — отдельная проверка безопасности. Рабочий HTTPS не подтверждает отсутствие угроз и не снимает такую блокировку. Раскройте «Подробнее об угрозе» и сохраните причину. При предполагаемой ошибке отправьте ссылку и описание игры в [поддержку Яндекс Браузера](https://browser.yandex.ru/feedback/). Не отключайте защиту ради проверки и не просите школьников игнорировать предупреждение.

### Ручная проверка перед мероприятием

1. Запустите `start.bat` в папке проекта, дождитесь публичной ссылки и QR.
2. На Android и iPhone **выключите Wi-Fi** и откройте ссылку через мобильные сети.
3. Создайте комнату в панели организатора. Подключите оба устройства по коду, проверьте список участников и отсутствие расхода света в ожидании. Нажмите «Начать игру» в панели: оба телефона должны одновременно перейти в шахту. Проверьте видимость друг друга и сбор одного кристалла на обоих экранах.
4. Отключите интернет на телефоне на 10 секунд, включите и проверьте возвращение в ту же шахту с прежними очками.
5. Проверьте обычный вопрос, ползунок, подсказку, штраф выхода, бонусы, лестницу и финал.
6. Завершите комнату из панели: игроки должны увидеть сообщение. Откройте `/organizer` по **публичному** адресу: ожидается отказ в доступе.
7. Нажмите Ctrl+C, затем запустите заново: прежние комнаты должны исчезнуть, а временная ссылка — обновиться.

Эмуляция мобильного браузера не заменяет проверку настоящих Android/iPhone и внешней мобильной сети. Работа Cloudflare зависит от сети, оператора и доступности сервиса; приготовьте запасную точку доступа. Исходящие подключения должны разрешать Cloudflare Tunnel (обычно TCP/UDP 7844; запуск Quick Tunnel здесь использует HTTP/2).

## Структура

- `index.html`, `assets/`, `questions.json` — существующая игра и ресурсы.
- `server/game.ts`, `world.ts`, `cities.ts`, `protocol.ts` — серверная логика и проверка сообщений.
- `server/index.ts` — HTTP, WebSocket и административные маршруты.
- `public/network.js` — соединение и восстановление; `public/organizer.*` — панель.
- `scripts/launch.cjs`, `start.bat`, `prepare.bat` — запуск и подготовка.
- `scripts/build-portable.ps1` — переносимая Windows-сборка.
- `server/*.test.ts`, `scripts/check-browser.cjs` — проверки.

Рекомендуемый коммит: `feat: добавить серверный мультиплеер и запуск выездной игры через Cloudflare Tunnel`.
